Crew isolation from the captain's global Claude Code config - end-to-end evidence
=================================================================================

How this was produced (both runs, 2026-09-02, Claude Code 2.1.258):
  1. A real `bin/fm-spawn.sh <id> <project> --scout` with harness=claude spawned a
     scout into a fresh disposable git worktree. tmux was faked only so the launch
     command is captured instead of typed; every other path (worktree, state,
     busy-state arm, the .claude/settings.local.json turn-end wiring) is the real one.
  2. That exact launch shape was then RUN for real, non-interactively
     (`--output-format stream-json --verbose -p ...`), inside the spawned worktree,
     against the captain's live ~/.claude config.
  3. The scout's own context stream was searched for the three global-hook
     injections that caused the incident, and firstmate's busy-state record was
     sampled during and after the turn.

The only difference between the two runs is whether `--setting-sources project,local`
was passed to the manually executed launch. fm-spawn.sh always emits the flag now,
so the "launch command" line is identical in both transcripts; the BASELINE run
deliberately strips it when executing, to reproduce the pre-fix condition.
